# Ревью хука G1 человеком

Kit version: 1.0.0 · Требование: CLAUDE.md / AGENTS.md («critical work also needs human review»), QA-01, SEC-07

Хук G1 — единственный механизм, который на практике останавливает агента. Шесть раундов
автоматического ревью безопасности его одобрили, но по правилам комплекта код такого уровня
должен посмотреть человек. Эта страница — что именно смотреть и как записать результат.
Время: 1–2 часа.

## 1. Что читать

| Файл | Что в нём | На что смотреть |
|---|---|---|
| `adapters/shared/hooks/g1_guard.py` | сам хук (≈500 строк) | `main()` — порядок проверок; `check_path()`; `decide()`; обработка ошибок в `__main__` |
| `adapters/shared/hooks/README.md` | описание поведения | совпадает ли с кодом; устраивают ли вас известные ограничения (§10) |
| `adapters/<среда>/install.py`, `adapters/shared/uok_install.py` | установщики | что они меняют в проекте; что не трогают пользовательское |
| `.claude/settings.json` / `.qoder/settings.json` / `.cursor/hooks.json` / `.codex/hooks.json` | регистрация в вашем проекте | команда хука, правила `deny`/`ask` |

## 2. Вопросы для проверки

Отвечайте «да / нет / не знаю» и записывайте замечания.

1. **Секреты.** Хватает ли списка `DENIED_GLOBS` и `SECRET_PATTERNS` для ваших проектов? Есть ли у вас
   секреты с другими именами (например `*.tfvars`, `service-account*.json`)? Их нужно добавить.
2. **Границы проекта.** Устраивает ли вас, что основная сессия может читать файлы вне проекта, а
   писать — нет?
3. **Подтверждения.** Список опасных операций (раздел 5 README): чего не хватает для вашей
   инфраструктуры (например `kubectl rollout`, `aws s3 rm`, `psql -c "DELETE…"`)?
4. **Отказ при ошибке.** Хук при собственной ошибке пропускает вызов для основной сессии (кроме
   записи и MCP) и блокирует для исполнителей. Согласны?
5. **Удалённый хук.** Если файл хука пропал, Claude Code блокирует все вызовы (проверено). Cursor с
   `failClosed: true` — тоже. Вам это подходит или нужен другой компромисс?
6. **Режимы.** Для ваших проектов достаточно `standard` или нужен `strict`?
7. **Среды без идентичности агента** (Cursor, Codex): правила для исполнителей там только
   инструкции. Это приемлемо?
8. **Ложные срабатывания.** Не мешают ли вам `ask` на `echo rm -rf`, запрет `curl` правилом
   `permissions` и подобное?

## 3. Как проверить самому

```bash
python3 -I UNIVERSAL-ORCHESTRATOR-KIT/adapters/shared/hooks/test_g1_guard.py
```

Ручная проверка одного события (подставьте свой путь):

```bash
echo '{"tool_name":"Read","tool_input":{"file_path":"'"$PWD"'/.env"}}' | python3 -I .orchestrator/hooks/g1_guard.py
```

Ожидается JSON с `"permissionDecision": "deny"`. Журнал решений: `.orchestrator/audit/g1.log`.

## 4. Запись результата

Добавьте в отчёт об установке (`handoff/INSTALLATION-REPORT-*.md`) раздел:

```markdown
## Human review of G1 (YYYY-MM-DD)
Reviewer: <имя>
Version reviewed: <git commit>
Verdict: approved | approved with changes | rejected
Findings: <список или «нет»>
Changes requested: <список или «нет»>
```

До такой записи зрелость адаптеров не поднимается выше `integration_tested`.
